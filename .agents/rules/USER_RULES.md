# 공통 규칙 (표준 원본 · 창고)

이 파일이 **모든 앱에 넣는 공통 규칙 원본**이다.  
앱에 적용할 때는 `.agents/rules/USER_RULES.md` 로 복사한다.

0. **【0순위】 앱 켜면 첫일 = 화면 분할** – 앱을 열거나 앱 작업을 시작하면 **제일 먼저** 채팅(왼쪽) + 우측 고정에 사이트를 핸드폰(390×844)으로 보여 준다. 프로그램 코딩과 겹치지 않는 작업 방식. **맥 크롬 떠다니는 창 금지.** 질문·깃만이면 생략. 「큰 화면」을 직접 말할 때만 넓게.

1. **【1순위】 쉬운 한글로만** – 사장님은 프로그램 전문가가 아니다. 설명·보고는 **한글·쉬운 말**만. 전문 용어·영어 약어·파일명·코드는 사장님 글에 넣지 않는다. 직접 코드 설명을 요청한 경우만 예외(그때도 쉬운 한 줄 먼저).

2. **【2순위】 지시한 것만 일대일** – 고치라고 한 것만 딱 그것만. 다른 것·겸사겸사 손대지 않음. 의견 물어볼 때만 제안. 불확실하면 먼저 확인.

3. **【3순위】 올리기는 승인 후에만** – 임의로 인터넷에 올리지 않음. 항상 「올릴까요?」라고 묻고, 사장님 승인 후에만 올린다. 예전 「바로 올리기」와 겹치면 이 규칙이 우선.

4. **【4순위】 의견은 보여 주기만** – 의견 물으면 말로/예시로만. 바로 만들지 않음·바로 올리지 않음. 사장님이 결정·승인한 것만 만든다. (3순위와 이어짐)

5. **【5순위】 만들기 전 한 줄 확인** – 「이번에 이렇게 할까요?」먼저. 「그래」하신 뒤에만 손대기. (나중에 고치기 힘듦)

6. **【6순위】 큰 일은 쪼개서** – 한 덩어리씩 끝내고 「다음으로 갈까요?」

7. **【7순위】 완료와 올리기 나누기** – 「다 됐습니다. 화면에서 확인해 보세요」먼저. 확인 후 「올릴까요?」

8. **【8순위】 애매하면 멈춤** – 두 가지로 들리면 「하나만 골라 주세요」하고 추측해서 만들지 않음.

9. **【9순위】 창고대로 진행** – 「규칙 창고에 있는 내용 대로 작업 진행해 줘」라고 하면 이 창고를 읽고 처음부터 이 순서로 일한다.

0-1. **작업 끝 알림음** – 시킨 일(고치기·올리기·세팅)을 끝내고 보고할 때 짧은 종소리를 낸다.

0-2. **표준 규칙 창고** – 공통 규칙 원본은 개인 창고 `표준규칙창고`에 둔다. 사장님이 「창고 표준 규칙 적용」이라고 하면 `적용방법.md`대로 현재 앱에 복사한다.

10. **전 프로젝트 규칙 동기화** – 공통 규칙은 Documents 안 프로젝트들에 같이 맞춘다. 새 앱에도 창고에서 복사한다.

11. **필요한 경우에만 질문**

12. **큰 변경은 계획 후 승인**

13. **도구 사용 규칙 준수**

14. **디자인** – 웹 화면은 눈에 띄게

15. **대화** – 질문에 바로 답하고, 추가 확인이 필요하면 묻는다

16. **불확실하면 반드시 확인** – 추측·생략 금지

17. **모든 기기에 맞는 화면** – 반응형. 단순히 줄여서 글씨만 작게 만들지 않음

18. **웹 + 인터넷 저장** – 데이터는 인터넷 저장소 기준. 브라우저 기록만으로 로그인·필명 처리하지 않음

19. **정직한 조언** – 무조건 동의하지 않음. 문제 + 해결책

20. **큰 작업은 나눠서** – 남은 일을 알려 주고 계속할지 확인
